# Build notes / 构建说明

## English

You need Windows x64, the .NET 10 SDK (see `global.json`), and the Visual Studio **Desktop development with C++** workload. NativeAOT links the agent with the MSVC toolchain. Package versions are central in `Directory.Packages.props`. Shared settings are in `Directory.Build.props`. Every in-repo library is a `ProjectReference`.

```powershell
dotnet build SuperMemoAssistant.slnx          # whole solution
dotnet test  --solution SuperMemoAssistant.slnx
```

`dotnet test` uses the Microsoft.Testing.Platform runner. `global.json` sets this.

- **Output:** `artifacts\app-dev` (ignored by git) holds `SuperMemoAssistant.exe`, `PluginHost.exe`, and `SuperMemoAssistant.Hooks.Agent.dll`, the NativeAOT component that connects SMA to SuperMemo. When you build the app, the build publishes this component and builds PluginHost into the same folder. SMA treats any folder named `app-dev` as a development run. Installed copies run from `%LocalAppData%\SuperMemoAssistant\current` (Velopack).
- **Integration component:** `src/Core/SuperMemoAssistant.Hooks.Agent` must stay reflection-free (NativeAOT). Its contract with SMA is `SuperMemoAssistant.Hooks.Common`.
- **SuperMemo builds:** SMA checks at start that it supports the installed SuperMemo 20 build. Unit tests cover the verified build.
- **PDF engine:** `SuperMemoAssistant.Pdfium` binds the PDFium C API with `LibraryImport`. The native `pdfium.dll` comes from the `bblanchon.PDFium.Win32` package. PDFium is not thread-safe, so call it from one thread at a time. `SuperMemoAssistant.Pdfium.Wpf` is the WPF viewer control. The tests in `src/Tests/SuperMemoAssistant.Tests/Pdfium` use the real `pdfium.dll`. To save the off-screen viewer renders as PNG files, set `SMA_PDF_VIEWER_PNG` to a folder.
- **Command palette:** `src/Core/SuperMemoAssistant.Core/SMA/Commands` holds the palette: the registry, the fuzzy matcher, the model, and the window. Each process publishes its global hotkeys through `HotKeyManager.PublishCommands`; plugins send them to SMA with `ISuperMemoAssistant.RegisterCommand`. The tests in `src/Tests/SuperMemoAssistant.Tests/Commands` cover the matcher, the model, the hotkey publishing, and the named-pipe registration. They also render the window off-screen. To save those renders as PNG files, set `SMA_PALETTE_PNG` to a folder.
- **End-to-end test:** `AgentEndToEndTests` runs a copy of SuperMemo 20 on a hidden desktop inside a kill-on-close job object. It takes a snapshot of the registry keys that SuperMemo rewrites and restores them afterward. The test is skipped unless `SMA_E2E=1`. The test finds SuperMemo from `SMA_SM_ROOT`, else from the `sm20.exe` that SMA is set up with, else from the program registered for `.kno` files. The test writes progress to `%TEMP%\sma-e2e.log`.
- **Full-app end-to-end tests:** `AppStartupEndToEndTests` runs the built app on a hidden desktop with a temporary profile (`SMA_APPDATA_DIR`, `USERPROFILE`, `LOCALAPPDATA`). One test seeds the Template plugin. The other test seeds every plugin and opens a sandboxed SuperMemo 20 with `-c <collection>`. They write progress to `%TEMP%\sma-app-e2e.log`.
- **Installer end-to-end test:** `InstallerEndToEndTests` installs `artifacts\releases\SuperMemoAssistant-win-Setup.exe` silently into the temporary profile. Then it runs the installed app. Run `build\pack.ps1` first. The test removes the uninstall key and the shortcuts that Setup creates. It writes progress to `%TEMP%\sma-installer-e2e.log`.
- **Test isolation:** All end-to-end tests share one xUnit collection and run serially. They kill their processes through a kill-on-close job object.
- **Plugins:** Each plugin builds to its own `bin\x64\Debug` folder with all its dependencies (`EnableDynamicLoading`, set in `src/Plugins/Directory.Build.props`). PluginHost resolves dependencies through the `deps.json` of the plugin. Then it falls back to the application folder.
- **Packaging:** Run `pwsh build\pack.ps1`. It publishes the app, and it publishes the eleven bundled plugins for `win-x64` into `Plugins\` next to the app (the list is `$bundledPlugins` in the script). It removes plugin assemblies that are identical to the copies of the app. Then it runs the pinned `vpk` tool (`.config\dotnet-tools.json`). It produces `Setup.exe`, a full package, a portable zip, and the update feed in `artifacts\releases`. The script never runs the installer.
  With `-SignThumbprint <thumbprint>` (a code-signing certificate in your certificate store), the script signs the release; otherwise the result is unsigned. The release job of CI signs with the project's certificate, see [docs/plugin-feed.md](plugin-feed.md).
- **Plugin feed:** Run `pwsh build\pack-plugins.ps1`. It packs each plugin in `build\plugin-feed\catalog.json` as a NuGet package. Then it writes a static NuGet v3 feed and the SMA catalog `plugins.json` into `artifacts\feed`. `src/Tools/SuperMemoAssistant.PluginFeed` writes the packages and the feed. It rejects a package that SMA would refuse to start. To reuse the app that `build\pack.ps1` published, add `-AppPublishDir artifacts\publish`.
  `PluginFeedTests` serves a generated feed from a loopback HTTP server. Then it lists and installs a plugin through the PluginManager code of SMA. To install every real package too, set `SMA_PLUGIN_FEED` to the `artifacts\feed` folder. For the feed URLs, the package layout, and third-party plugins, see [Releases and the plugin feed](plugin-feed.md).
- **Themes:** `src/Themes/SuperMemoAssistant.Themes` is the theme engine. `src/Plugins/SuperMemoAssistant.Plugins.Themes` is the optional plugin: it is only in `build\plugin-feed\catalog.json`, not in the `$bundledPlugins` list of `build\pack.ps1`, and a test enforces that. `src/Tests/SuperMemoAssistant.Themes.Tests` is a fast test project (about 40 seconds). Most of its tests compare the C# code with recordings of the former Python tool, in its `Golden` folder (see the `README.md` there for what each file holds and when to change one). The tests that need the real `sm20.exe` use the untouched copy (`SMA_SM20_ORIGINAL`; by default `smcards-backups\exe\sm20.exe.original` in the SuperMemo folder, which is found as described above) and skip without it. Two opt-in end-to-end tests (`SMA_E2E=1`) cover the plugin in `AppStartupEndToEndTests`: one loads it in a real `PluginHost` and checks that its hook is registered; the other runs a full session with Themes enabled on a sandbox copy of SuperMemo and checks the order of registration, rebuild, start and the after-exit hook. They need `artifacts\app-dev` and the untouched exe. See [ADR 0003](decisions/0003-themes-optional-plugin-and-launch-hooks.md).
- **Agent skill:** `skills/supermemo-appearance` is the skill that drives `sma-cards` and the Themes plugin (`SKILL.md`; extra technical notes in a `references` folder stay local and are git-ignored). `SkillTests` checks that it has the right name and description, names no drive or user folder, and that its relative links open. When you change a `sma-cards` command or a plugin setting, change the skill text in the same commit. To use the skill, link the folder into the skills folder of your AI assistant, for example `New-Item -ItemType Junction -Path "$HOME\.agents\skills\supermemo-appearance" -Target "<repository>\skills\supermemo-appearance"`.
- **Card tool:** `src/Tools/SuperMemoAssistant.CardTool` builds `sma-cards`, a console tool for editing the cards of a collection while SuperMemo is closed: `status`, `collections`, `list`, `show`, `element-color`, `css show|set|unset`, `html replace|strip-style`, `theme list|show|status`, `backups`, `restore`, `snapshot`, and `diff`. It is a few lines that call `CardCommandLine` of the Themes engine. It is not part of the installer. It finds SuperMemo from `--sm-root`, then `SMCARDS_ROOT`, then the `sm20.exe` that SMA is set up with, then the `.kno` association. To get an exe that you can call from anywhere, run `dotnet publish src/Tools/SuperMemoAssistant.CardTool -c Release -o artifacts/tools/sma-cards`. Then run `artifacts\tools\sma-cards\sma-cards.exe --help`. The commands that change files (`element-color`, `css set`, `css unset`, `html replace`, `html strip-style`, `restore`) are dry runs until you add `--apply`. Each one backs up the files first and refuses to write while SuperMemo runs.
- **CI and release:** `.github/workflows/build.yml` builds and tests each push and pull request. A tag `vX.Y.Z` also runs `build\pack.ps1` and `vpk upload github`, which publishes the GitHub Release that installed copies update from. The same tag runs `build\pack-plugins.ps1` and deploys `artifacts\feed` to GitHub Pages. Push with `git push origin main --follow-tags`.
- **Warnings:** `Directory.Build.props` treats all warnings as errors. A clean build has 0 warnings.

## 简体中文

要求:Windows x64、.NET 10 SDK(见 `global.json`),以及 Visual Studio 的“使用 C++ 的桌面开发”工作负载(NativeAOT 需要 MSVC 工具链)。包版本集中在 `Directory.Packages.props`,公共设置在 `Directory.Build.props`,仓库内的库全部用 `ProjectReference` 引用。

```powershell
dotnet build SuperMemoAssistant.slnx          # 整个解决方案
dotnet test  --solution SuperMemoAssistant.slnx
```

- **输出目录:** `artifacts\app-dev`(已被 git 忽略),包含 `SuperMemoAssistant.exe`、`PluginHost.exe` 和 `SuperMemoAssistant.Hooks.Agent.dll`(连接 SMA 与 SuperMemo 的 NativeAOT 组件)。名为 `app-dev` 的目录会被识别为开发运行;安装版运行在 `%LocalAppData%\SuperMemoAssistant\current`(Velopack)。
- **集成组件:** `src/Core/SuperMemoAssistant.Hooks.Agent` 必须保持无反射(NativeAOT),它与 SMA 的契约是 `SuperMemoAssistant.Hooks.Common`。
- **SuperMemo 版本:** SMA 在启动时检查是否支持已安装的 SuperMemo 20 版本;单元测试覆盖已验证的版本。
- **PDF 引擎:** `SuperMemoAssistant.Pdfium` 用 `LibraryImport` 绑定 PDFium C API,原生 `pdfium.dll` 来自 `bblanchon.PDFium.Win32` 包。PDFium 不是线程安全的,同一时间只能在一个线程上调用。`SuperMemoAssistant.Pdfium.Wpf` 是 WPF 查看器控件。`src/Tests/SuperMemoAssistant.Tests/Pdfium` 中的测试使用真实的 `pdfium.dll`;把 `SMA_PDF_VIEWER_PNG` 设为某个目录,可把屏幕外渲染的查看器保存为 PNG。
- **命令面板:** `src/Core/SuperMemoAssistant.Core/SMA/Commands` 包含命令面板:注册表、模糊匹配、模型和窗口。每个进程通过 `HotKeyManager.PublishCommands` 发布自己的全局快捷键;插件用 `ISuperMemoAssistant.RegisterCommand` 把它们发送给 SMA。`src/Tests/SuperMemoAssistant.Tests/Commands` 中的测试覆盖匹配、模型、快捷键发布和命名管道注册,并在屏幕外渲染窗口;把 `SMA_PALETTE_PNG` 设为某个目录,可把渲染结果保存为 PNG。
- **端到端测试:** `AgentEndToEndTests` 在隐藏桌面上运行 SuperMemo 20 的副本,放在退出即终止的 Job 对象里,并快照/恢复 SuperMemo 会改写的注册表项。默认跳过;设置 `SMA_E2E=1` 运行,测试按以下顺序查找 SuperMemo:环境变量 `SMA_SM_ROOT`,SMA 配置的 `sm20.exe`,为 `.kno` 文件注册的程序。
- **完整应用端到端测试:** `AppStartupEndToEndTests` 在隐藏桌面上用临时用户配置(`SMA_APPDATA_DIR`、`USERPROFILE`、`LOCALAPPDATA`)运行已构建的应用:一个测试预置 Template 插件,另一个预置全部插件,并用 `-c <集合>` 打开沙盒中的 SuperMemo 20。
- **安装程序端到端测试:** `InstallerEndToEndTests` 把 `artifacts\releases\SuperMemoAssistant-win-Setup.exe` 静默安装到临时用户配置,然后运行安装后的应用;需要先运行 `build\pack.ps1`。测试会删除 Setup 创建的卸载注册表项和快捷方式。
- **测试隔离:** 所有端到端测试属于同一个 xUnit 集合并按顺序运行,通过退出即终止的 Job 对象结束其进程。
- **插件:** 每个插件构建到自己的 `bin\x64\Debug` 目录并附带全部依赖(`EnableDynamicLoading`,见 `src/Plugins/Directory.Build.props`)。PluginHost 先按插件的 `deps.json` 解析依赖,再回退到应用目录。
- **打包:** 运行 `pwsh build\pack.ps1`,它会发布应用,并把十一个内置插件按 `win-x64` 发布到应用旁的 `Plugins\`(列表是脚本中的 `$bundledPlugins`),删除与应用自带副本相同的插件程序集,然后运行固定版本的 `vpk` 工具(`.config\dotnet-tools.json`),在 `artifacts\releases` 生成 `Setup.exe`、完整包、便携 zip 和更新源。脚本不会运行安装程序。传入 `-SignThumbprint <指纹>`(证书存储中的代码签名证书)时生成物会被签名,否则未签名;CI 的发布作业使用本项目的证书签名,见 [docs/plugin-feed.zh-CN.md](plugin-feed.zh-CN.md)。
- **插件源:** 运行 `pwsh build\pack-plugins.ps1`,它把 `build\plugin-feed\catalog.json` 中的每个插件打包为 NuGet 包,再把静态 NuGet v3 源和 SMA 目录 `plugins.json` 写入 `artifacts\feed`。添加 `-AppPublishDir artifacts\publish` 可复用 `build\pack.ps1` 发布的应用。插件源的网址、包布局和第三方插件见[发布与插件源](plugin-feed.zh-CN.md)。
- **Themes:** `src/Themes/SuperMemoAssistant.Themes` 是主题引擎。`src/Plugins/SuperMemoAssistant.Plugins.Themes` 是可选插件:它只在 `build\plugin-feed\catalog.json` 中,不在 `build\pack.ps1` 的 `$bundledPlugins` 列表中,并且有测试强制这一点。`src/Tests/SuperMemoAssistant.Themes.Tests` 是快速测试项目(约 40 秒)。它的大部分测试把 C# 代码与原 Python 工具的记录数据(位于其 `Golden` 文件夹,其中的 `README.md` 说明各文件的内容以及何时可以修改)对照。需要真实 `sm20.exe` 的测试使用未修改的副本(`SMA_SM20_ORIGINAL`;默认是 SuperMemo 文件夹中的 `smcards-backups\exe\sm20.exe.original`,该文件夹的查找方式见上文),没有它时跳过。`AppStartupEndToEndTests` 中有两个需手动开启的端到端测试(`SMA_E2E=1`):一个在真实的 `PluginHost` 中加载插件并检查其钩子已注册;另一个在 SuperMemo 的沙盒副本上用启用 Themes 的状态运行完整会话,并检查注册、重建、启动和退出后钩子的顺序。它们需要 `artifacts\app-dev` 和未修改的 exe。见 [ADR 0003](decisions/0003-themes-optional-plugin-and-launch-hooks.md)。
- **卡片工具:** `src/Tools/SuperMemoAssistant.CardTool` 构建 `sma-cards`,一个在 SuperMemo 关闭时编辑集合中卡片的控制台工具,命令有 `status`、`collections`、`list`、`show`、`element-color`、`css show|set|unset`、`html replace|strip-style`、`theme list|show|status`、`backups`、`restore`、`snapshot` 和 `diff`。它只有几行代码,调用 Themes 引擎的 `CardCommandLine`,不在安装程序中。它依次从 `--sm-root`、`SMCARDS_ROOT`、SMA 配置的 `sm20.exe`、`.kno` 关联程序中查找 SuperMemo。要得到可以从任何位置调用的 exe,运行 `dotnet publish src/Tools/SuperMemoAssistant.CardTool -c Release -o artifacts/tools/sma-cards`,然后运行 `artifacts\tools\sma-cards\sma-cards.exe --help`。会修改文件的命令(`element-color`、`css set`、`css unset`、`html replace`、`html strip-style`、`restore`)在加上 `--apply` 之前只是试运行;每个命令先备份文件,并在 SuperMemo 运行时拒绝写入。
- **智能体技能:** `skills/supermemo-appearance` 是驱动 `sma-cards` 和 Themes 插件的技能(`SKILL.md`;额外的技术笔记放在本地的 `references` 文件夹中,已被 git 忽略)。`SkillTests` 检查它有正确的名称和说明、不含盘符或用户文件夹路径、相对链接都能打开。修改 `sma-cards` 的命令或插件设置项时,请同时更新这里的文字。要使用该技能,请把该文件夹链接到 AI 助手的技能文件夹,例如 `New-Item -ItemType Junction -Path "$HOME\.agents\skills\supermemo-appearance" -Target "<仓库>\skills\supermemo-appearance"`。
- **CI 与发布:** `.github/workflows/build.yml` 对每次推送和拉取请求进行构建和测试;推送 `vX.Y.Z` 标签时还会运行 `build\pack.ps1` 和 `vpk upload github` 发布 GitHub Release,并运行 `build\pack-plugins.ps1`,把 `artifacts\feed` 部署到 GitHub Pages。推送时使用 `git push origin main --follow-tags`。
- **警告:** `Directory.Build.props` 把所有警告视为错误,完整构建为 0 个警告。
